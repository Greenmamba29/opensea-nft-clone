The biggest violations of ARCHITECTURE.md's own rules are data duplication: the mall domain data exists in three hand-synced copies (netlify/functions/_data.ts, src/lib/mallData.ts, and an inline FALLBACK_OVERVIEW in MallOSPage.tsx) and the MallOverview type is redeclared in api.ts rather than derived from _data.ts — directly contradicting rules 2 ('one concern, one owner') and 3 ('_data.ts is the single schema'). There is clear dead code from the OpenSea-clone origin: src/components/ConnectWalletModal.tsx and OnboardingModal.tsx are imported nowhere, src/lib/airtable.ts is an empty stub that also reads a VITE_-prefixed API key (client-bundle exposure hazard), and src/data/mock.ts carries several unused exports including a sidebarLinks list pointing at pre-/mall legacy routes. Route map is otherwise consistent — every Link/navigate target resolves to a route declared in main.tsx; the dead interactive elements are href="#" placeholder links in Footer, SiteFooter, and the MallOS left-nav.
  DEAD [src/components/Footer.tsx] Terms of Service -- href="#" placeholder anchor, navigates nowhere.
  DEAD [src/components/Footer.tsx] Privacy Policy -- href="#" placeholder anchor, navigates nowhere.
  DEAD [src/components/grahmos/landing/SiteFooter.tsx] Footer column links (multiple, rendered from arrays) -- All rendered as <a href="#"> — pure placeholders.
  DEAD [src/pages/grahmos/MallOSPage.tsx] Left-nav items: Storefronts, Lease Inventory, Mall Placement, Merchants, Buyers, Quotes, Sourcing, Agents, Analytics -- NAV items render as <a href="#"> (lines ~239-248); only 'Overview' is the real visible page.
  DEAD [src/components/ConnectWalletModal.tsx] Corporate Login / SSO / Supplier Portal options -- Entire component is orphaned — imported by no file, so these CTAs are unreachable dead code.
  DEAD [src/components/OnboardingModal.tsx] Onboarding modal CTAs -- Component imported nowhere; unreachable dead code.
  HIGH [netlify/functions/_data.ts + src/lib/mallData.ts + src/pages/grahmos/MallOSPage.tsx] Triple duplication of domain data violating ARCHITECTURE.md rules 2 & 3. AISLES/STOREFRONTS/PRODUCTS are hand-copied between _data.ts and mallData.ts (comment literally says 'Keep in sync with src/lib/mallData.ts'), and the full MALL_OVERVIEW object is copy-pasted a third time as FALLBACK_OVERVIEW in MallOSPage.tsx (lines 88-141). Shapes have already drifted: _data.ts Storefront has category/status/assignedAgent/monthlyLease; mallData MallStorefront has tagline/monthlySales/customers/fromPrice; Order uses createdAt+storefrontId server-side vs date+storefront-name client-side. The stated 'typed boundary' is fiction — client types do not derive from _data.ts.
  HIGH [src/lib/airtable.ts] Dead stub AND a security hazard: syncProductToAirtable/fetchProductsFromAirtable only console.log ('Implementation for Phase 2'), the file is imported nowhere — but it exports AIRTABLE_API_KEY = import.meta.env.VITE_AIRTABLE_API_KEY. Any VITE_-prefixed secret is inlined into the public client bundle; per ARCHITECTURE.md §7 Airtable belongs behind Netlify functions, never in the SPA. Delete the file.
  MED [src/lib/api.ts] MallOverview, Storefront, and Quote types are re-declared here instead of being imported/derived from netlify/functions/_data.ts ('the single schema'). Any server-side schema change silently breaks the contract — there is no compile-time link across the wire boundary.
  MED [src/components/ConnectWalletModal.tsx, src/components/OnboardingModal.tsx] Orphaned components — imported by no file in src/. ConnectWalletModal is the last consumer of mock.ts walletOptions. Dead weight from the OpenSea-clone era; safe to delete.
  MED [src/data/mock.ts] Legacy OpenSea-era data with multiple unused exports: featuredCollections, traitItems, categories, and sidebarLinks are imported nowhere (sidebarLinks also points at pre-/mall routes like /rankings, /activity, /drops that no longer exist in main.tsx). Also nftItems uses Math.random() at module scope, so 'prices' and 'rarity' on CollectionPage/NFTDetailPage change on every page load — nondeterministic UI.
  MED [src/pages/CollectionPage.tsx, src/pages/NFTDetailPage.tsx, src/pages/TokensPage.tsx] These /mall routes still render NFT-clone mock content ('Industrial Pump Model #1000', traits, chains) from src/data/mock.ts instead of the mall domain (mallData.ts). routeEngine.ts even routes every 'Visit <merchant>' stop to the generic /mall/collection page regardless of which storefront, so Directions Mode store stops all land on the same OpenSea-legacy page — a real product-flow inconsistency, not just cosmetic.
